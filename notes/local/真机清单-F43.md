# F43 真机清单（Alacritty / Devuan）

二进制：`target/release/pi-rs`。以 `--version` 实际输出为准（须无 `-dirty`）；
本批最终回复给出对应的 commit 与 sha256 前缀。

## 零、开始前
`pgrep -af 'pi-rs|runner.mjs'` 必须为空（用这条写法并排除本行自身）。

## 一、退出时只输出本次会话的日志（本批主项）
1. 连续启动 `pi-rs` 并退出 **3 次**（每次不输入内容，直接 `Ctrl+D`）。
2. 每次退出后观察终端上输出：应当**只有本次**那一段日志（例如 3 行左右），
   不得出现前几次的内容（改前：第 N 次会输出前 N-1 次的全部）。
3. 检查 `<你的配置目录>/extensions.log`：内容应当**累积**（3 次会话的日志都在），
   没有被清空或覆盖。

## 二、日志容量治理
若 `extensions.log` 曾超过 1 MiB：下次启动时应被截断为最近约 256 KiB
（从下一个换行开始，不会切出半行）。这是有意行为，不是丢日志的缺陷。

## 三、ctrl+x 无消息提示（R2 修复）
在**没有任何助手消息**时按 `Ctrl+X`：应显示红色 ` Error: No agent messages to copy yet.`
（带 `Error: ` 前缀；改前是没有前缀的灰色状态行）。

## 四、底栏分支名（R2 复测）
在 git 仓库里启动，底栏第一行应为 `<cwd 缩写> (<分支名>)`，
例如 `/tmp/r2repo (recover)`；detached HEAD 时括号内是 `detached`。

## 五、回归（各 5 次）
1. 退出后立刻按 ↑：全扩展与 `-ne` 各 5 次，出现 `^[[A` 次数 = ___ / ___（预期 0/5）。
2. `strace -f -tt -e trace=ioctl -o /tmp/ex.txt pi-rs` 后
   `grep -E 'TCSETS' /tmp/ex.txt | tail -6 | awk '{print $1, $3}'`
   —— 只应出现 pi-rs 自己的 pid。
