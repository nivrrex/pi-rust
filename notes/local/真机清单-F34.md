# F34 真机清单（Windows 部分）

以下步骤在 Linux 上无法验证，需 Windows 真机确认。

## W1 jiti 探测
1. 不设 `PI_JITI`，只装 pnpm 全局 jiti：
   `pnpm i -g jiti`，确认存在
   `%LOCALAPPDATA%\pnpm\global\v11\<hash>\node_modules\jiti\package.json`（`name` 为 `jiti`）。
   预期：`pi-rs` 启动后 `[Extensions]` 列出 `.ts` 扩展，**不出现**"未找到 jiti"。
2. 同上但存在**两个** hash 目录（旧版本残留）：预期取 `package.json` 修改时间最新的那个，仍能加载。
3. 都不装：预期启动成功但 `.ts` 扩展被跳过，stderr **列出已搜索的全部目录**，并给出
   `set PI_JITI=C:\Users\<you>\AppData\Local\pnpm\global\v11\<hash>\node_modules\jiti` 示例。
4. `set PI_JITI=<目录>` 显式指定（含空格路径，如 `C:\Program Files\jiti`）：预期优先命中。

## W2 路径与启动
1. 扩展目录含空格（`C:\Program Files\proj`）与中文：扩展能加载，`[Extensions]` 名称正常。
2. 反斜杠/盘符：`--session C:\Users\u\.pi\sessions\x.jsonl` 能加载，页脚与 `/context` 正常。
3. UNC 路径（`\\server\share\proj`）：若无法访问应给出明确错误而不是崩溃。
4. `canonicalize` 后的 `\\?\` 前缀不得出现在扩展路径里（表现为 Node 报 `ERR_MODULE_NOT_FOUND` 或
   `EINVAL`）——本批已剥离，验证时重点看是否有该错误。
