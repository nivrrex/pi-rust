# F35 真机清单（Windows / 语法高亮 / 引用渲染）

## 一、Windows 扩展加载（承接 F34）
1. 只装 pnpm 全局 jiti，不设 `PI_JITI`：启动后 `[Extensions]` 应列出 `.ts` 扩展，无"未找到 jiti"。
2. `%LOCALAPPDATA%\pnpm\global\v11\<hash>` 存在**多个** hash（旧版本残留）：取 `package.json`
   修改时间最新的，仍能加载。
3. hash 目录是符号链接 / junction：仍能读到 `package.json`（已用 Linux 符号链接单测覆盖，
   Windows 真机确认 junction 行为一致）。
4. 扩展目录含空格 / 中文 / UNC：加载正常；错误时应给 `file://` 形式的路径而不是裸 `C:\`。

## 二、代码块语法高亮
1. 让模型输出 ```rust / ```bash / ```python / ```js 代码块：
   - rust：`fn` 蓝色、`main` 米黄、`"str"` 橙色、`// 注释` 绿色、`println!` 青绿；
   - bash：`echo` 青绿、`"str"` 橙、`# 注释` 绿；`ls` 等外部命令**不着色**（与 TS 一致）。
2. 输出 ```json / ```yaml / ```markdown：**整行** 单一色（ref eager 集里没有这些语言）。
3. ```go / ```c / ```java：当前**整行单一色**（分词器未实现，见 LIMITATIONS 第 11 条）。

## 三、Markdown 引用与表格
1. 嵌套引用（`> >`）与引用内空行：每层前缀 ` │ `，空行输出 ` │ │`。
2. 引用内列表：` │ │ - 项`（前缀与标记之间只有一个空格）。
3. 表格：表头只加粗单元格内容（`│` 分隔符不加粗）；CJK 单元格按显示宽度折行。
4. 分隔线 `---`：整行 `gray`（不是 dim）。
