## 二、strace 复核（确认"最后一次 TCSETS 的进程是 pi-rs 本身"）
```
strace -f -tt -e trace=ioctl -o /tmp/ex.txt pi-rs
```
退出后查看：
```
grep -E 'TCSETS' /tmp/ex.txt | tail -6
grep -E 'TCSETS' /tmp/ex.txt | tail -6 | awk '{print $1}' | sort -u
```
- 预期：最后一个 `TCSETS` 的 pid **是 pi-rs 自己的 pid**；
  不应再出现"pi-rs 的 pid 之后、另一个 pid（node）"的 `TCSETS` 行。
- 改前（F40 时代）你会看到：pi-rs 恢复 cooked → 约 6ms 后 pi-rs 退出 →
  约 12ms 后 node 的 pid 对 fd 1、fd 2 各做一次 `TCSETS`（写回 `ICANON|ECHO`）。

## 三、粘贴（bracketed paste 复位）
退出后立刻 `Ctrl+Shift+V` 粘贴一行命令：不得看到字面 `^[[200~` / `^[[201~`。

## 四、已知影响面（不是回归，请勿按缺陷上报）
- 扩展进程的 `process.stdout`/`process.stderr` 现在都是**管道**（不再是 tty）：
  - `process.stdout.isTTY` 为 `false`、`process.stdout.columns` 为 `undefined`；
  - 扩展的 `console.log`（stdout）会被宿主转到 **stderr**，不再直接写终端 stdout。
  已核对本机 10 个扩展，均不依赖 `isTTY`/`columns`。
- 退出时会先等扩展的 `session_shutdown` 处理器（最多 1s），再等宿主进程退出（最多 1s）。
  实测退出耗时 55.8 → 55.9 ms（TS 60.3 ms），无可见延迟。
