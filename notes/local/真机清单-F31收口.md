# F31 收口 · 真机验证清单

验证对象：`pi-rs`（F31 批次末，HEAD 见提交记录）。原版对照：pi 0.87.1。
每项给出「操作步骤 / 预期现象」，可一次性跑完。

## 一、Armbian（sysvinit，x86_64 或 arm64）
1. `pi-rs --version`、`pi-rs --help` 正常；TUI 启动无 systemd 相关报错。
2. 正常退出：启动后直接 Ctrl+D ⇒ **10 个扩展全部加载完毕**、进程退出 **<500ms**、无「会话写入超时」告警。
3. 底栏：`↑0 ↓0 0.0%/128k (auto)` 形态、模型名与 thinking 档位显示正确。
4. `/context`、`/skills`：`[Context]`、`[Skills]` 段落存在；长行在 80/120 列下折行不越界。
5. `!echo hi`：块边框整宽、` $ echo hi`、输出 ` hi`、无 `(exit 0)` 状态行。
6. `!!echo hi`：同上，但**不进上下文**（再问一句模型，回复里不应引用该输出）。
7. `!sleep 30` 后按 Esc：块内出现取消状态，进程不再等待。
8. `!seq 1 60`：折叠为最后 19 行 + `... N more lines (ctrl+o to expand)`，Ctrl+O 展开。
9. **只有 `!` 命令的会话**（启动 → `!echo x` → Ctrl+D）：`~/.pi/sessions`（或 `--session-dir`）**不新增 jsonl**，
   且**不打印** `To resume this session`。
10. remote-control 扩展：连接正常、`getSessionId()` 不报 `is not a function`。
11. pi-ai-summary：启动无 `[PI_AI_SUMMARY_INSTALL_FAILED]`。
12. jiti 多 hash 探测：扩展能加载（`pnpm` 全局目录 hash 变化后仍可加载）。

## 二、Windows（真机）
1. bash 可用（Git Bash / WSL），`!echo hi` 与 `!` 折叠、Esc 取消行为同 Linux。
2. 选择器窗口（模型/thinking）、Ctrl+P 档位切换无错行。
3. extension host 能拉起（node 路径正确），`[Extension issues]` 不出现。

## 三、WezTerm / kitty
1. kitty keyboard protocol：`flags=5` 生效，Ctrl+O、Esc、方向键正常。
2. 真彩色与 256 色：主题色一致，边框不断裂。
3. 粘贴多行（T84 场景）：不误触发送、回车按行生效。

## 已知限制（本批登记，验证时不必当缺陷）
1. **pi-secrets 对 `!` / `!!` 的脱敏不支持**：其实现依赖 `user_bash` 返回的 `{operations}.exec` 在 `onData` 里逐块脱敏
   （`Extensions_dev/pi-secrets/src/index.ts:302-319`）；我们的扩展宿主是独立进程，函数值无法跨进程调用 ⇒
   需要协议级改造（宿主反向请求执行 bash）。当前 `!` 的流式输出与会话 `output` 均为原文。
2. ~~`!` 后 footer 百分比约 1pp 残差~~ **已修复（C1）**：footer 改为复用 `estimate_context_tokens`
   （ref `compaction.ts:218-246` 的 usage+trailing 口径），`!echo`/`!!echo`/Esc 取消 三个场景与 TS 逐帧 same。
3. **S2d 主题变体与运行中态未逐帧对照**：取消/截断态只在 dark 下逐帧比对过；运行中态因 loader 逐帧变化未做定格对照。
