## 一、修复：把"超时丢前缀"改成记账式

旧实现两处会漏：①前缀按时间超时被丢 ⇒ `ESC[20` 丢掉、`1~` 落进正文（用户截图）；
②多段拆分时前缀被当"非标记"丢弃 ⇒ 整段 `200~` 漏出。

新实现（`crates/pi-cli/src/bracket_paste.rs`）：

| 状态 | 行为 |
|---|---|
| 空闲 + `Esc` | 暂扣（`ESC_HOLD_MS=40` 后放给编辑器），同时开一个 `pending` 记账 |
| `pending` + 字符补得齐 | 吞掉并继续累计（`""`→`"["`→`"[2"`→`"[20"`→`"[200"`） |
| `pending` + 补满 `[200~` / `[201~` | 前者进入正文收集、后者整体吞掉 |
| `pending` + 字符补不齐 | 把（未放行的 `Esc` +）前缀 + 当前字符**原样按正文交回**，不静默丢字 |
| `pending` + 非字符键 | `TextThen(前缀, 按键)`：正文先按 `Paste` 交回，按键照过（旧实现整段丢弃） |
| 长期无人理（`PENDING_IDLE_MS=5s`） | 残片按正文回吐 |

关键点：**时间不再丢弃任何字节**，因此无论拆成几段、间隔多长，结果只可能是
"完整按粘贴处理"或"完整按普通输入处理"，不会只漏尾巴。

| 回归（孤立 Esc、`Esc[A`、Tab/Ctrl+Enter、PasteBurst） | 既有用例 | 全绿 |

## 三、真机复验（60 次）

三通道 × 20 次，六类内容轮转（3 行 / 12 行 / 30 行 / 含 tab / 含中文 / 含 `~` 与 `[`）：

| 通道 | 通过 | 残片 | 误提交 | 备注 |
|---|---|---|---|---|
| `Shift+Insert`（SendInput 真实按键） | **20/20** | 0 | 0 | 未折叠时 `input` 与"tab 展开后长度"逐次相等 |
| 右键粘贴（SendInput 真实鼠标） | **20/20** | 0 | 0 | 同上 |
| `Ctrl+V` | 0/20（未粘贴） | 0 | 0 | 本机 WezTerm 未把 `Ctrl+V` 绑到粘贴（`input=0`），与 pi-rs 无关 |

统计（`v16-results.jsonl`）：`total=60, submitted=0`；脚本初版把"内容自带的 `1~`/`200~`"
（`tilde-bracket` 用例）误报为泄漏，逐行核对后：**真实残片 0 次**（那 6 条 `input==expected`
且屏幕内容就是用户粘贴的原文）。

事件侧：60 次运行的 `PI_TUI_EVENT_DUMP` 里 **`Esc` 事件仍为 0**——本机 WezTerm+ConPTY 把标记
整段吞掉，真机走的是键流路径；记账式逻辑由上面的矩阵单测覆盖。
